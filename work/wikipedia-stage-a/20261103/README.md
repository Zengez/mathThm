## Structure

For each worker N (1–4):
- `worker-N/needs_interpretation.jsonl` — high-priority source excerpts, one URL per row.
- `worker-N/mechanical_suggestions.jsonl` — proposals that must also be reviewed, one URL per row.
- `worker-N/PROMPT.md` — ready-to-use instructions and exclusive output branch.

The full `REPORT.json` summarizes completeness and counts. Each editorial worker writes only to their own branch, `work/wikipedia-stage-a/worker-N`, at `worker-N/editorial_decisions.jsonl`, ensuring no concurrent edits to the same records. Workers should skip disproportionate research: hold difficult content explicitly and continue.

The main/public `data/theorems.json` remains generated by the established Stacks publication pipeline. These Wikipedia candidates cannot be directly published without the relevant existing admission workflow.

## Provenance and limits

Captured top excerpts are rendered HTML text with LaTeX alternate text for mathematical expressions, **not authoritative verbatim source transcriptions**. Some Wikipedia pages include several distinct results, and the machine-selected paragraph may still not contain all needed hypotheses. Worker output is responsible for statement scope and correct separation, not mathematical truth/proof validation.
